# ScholarAgent 核心理念与能力说明

本文档用于毕业设计论文、开题/中期/答辩讲述和 README 导读。它的重点是把
ScholarAgent 讲成一个机制清楚、边界诚实、工程完整的科研调研 Agent 原型,
而不是泛泛地说成「接了一个大模型 API」。

## 一句话定位

ScholarAgent 是一个面向科研文献调研场景的自研自主智能体系统。项目从零实现
模型层、工具层、ReAct 执行循环、记忆系统、规划层、多智能体协作和评测框架,
使大语言模型能够在受控工具边界内完成论文检索、下载阅读、笔记沉淀和结构化
总结等任务。

## 核心理念

### 1. 大模型不是答案源,而是任务调度器

系统不把大模型当作一次性问答接口,而是让模型在每一步判断「是否需要工具」、
「调用哪个工具」和「拿到观察结果后如何继续」。真正执行搜索、下载、PDF 解析、
计算和记忆写入的是本地 Python 工具。这样可以把模型的语言能力和程序的确定性
边界结合起来。

对应实现:

- `scholaragent/agent.py`: 思考 -> 行动 -> 观察 的 ReAct 循环。
- `scholaragent/tool.py`: 工具基类、工具注册表、工具白名单和错误回传。
- `scholaragent/llm.py`: OpenAI 兼容模型接口,上层不关心具体模型厂商。

### 2. 科研调研是长流程,需要规划、记忆和协作

文献调研不是单轮问答。它通常包含检索候选论文、筛选代表工作、下载阅读、记录
结论、对比方法和总结开放问题等步骤。因此系统在基础 ReAct 循环上扩展了两种
更适合复杂任务的模式:

- `--plan`: 先拆解任务,逐步执行,每步后做反思质检,最后汇总。
- `--team`: 固定流水线为检索员、精读员、写作员,每个角色拥有不同提示词和工具白名单。

这种设计既控制了每个角色的上下文规模,也避免一个 Agent 同时拿到过多工具后行为
发散。

### 3. 工程系统必须能复现、能失败、能说明边界

项目保留离线假模型 `ScriptedLLM`,让核心循环和测试不依赖网络、不消耗 API 费用。
评测层把任务写成 JSONL,用关键词命中率和耗时生成报告,为 ReAct、规划、团队模式
提供消融对比。当前评测是初步框架,后续需要扩充任务集并加入人工复核。

## 系统能完成的任务

### 文献检索

用户给出英文关键词或研究主题后,系统可以调用 `arxiv_search` 检索论文,返回标题、
作者、arXiv 编号、日期和摘要。官方 arXiv 接口繁忙时,工具可切到 OpenAlex 的
arXiv 索引作为备用来源。

### 论文下载与分段阅读

系统可以根据 arXiv 编号下载 PDF,校验编号格式,避免路径穿越等不安全输入。阅读
论文时不会把全文一次性塞进上下文,而是按页和页内偏移分段返回,并提示下一次读取
位置。团队模式下还可以要求精读员持续阅读到工具确认全文读完。

### 笔记与长期记忆

系统支持两类沉淀:

- 研究笔记: 面向人阅读的 Markdown 笔记,适合保存论文要点和引用。
- 长期记忆: 面向 Agent 检索的 JSONL 记忆库,使用手写 BM25 和中英文分词召回相关事实。

目前长期记忆是关键词/字符 bigram 检索,不是向量语义检索;向量检索可以作为后续
扩展。

### 规划模式

`--plan` 适合多步复杂任务。流程是:

1. 规划师把任务拆成最多 6 个步骤。
2. 内层 Agent 对每一步使用 ReAct 和工具执行。
3. 反思器判断单步结果是否达标,必要时带改进建议重试一次。
4. 总结器把所有步骤结果综合成最终回答。

它的优势是复杂任务更稳,代价是耗时和模型调用次数增加。

### 多智能体团队模式

`--team` 适合完整调研流程。三个角色按固定顺序交接:

1. 检索员: 只负责搜索和筛选论文。
2. 精读员: 只负责下载、分段阅读、保存笔记和长期记忆。
3. 写作员: 只根据检索报告、精读笔记和已有记忆写综述。

当前团队模式是固定流水线,不是动态协商或自动派工;动态调度适合作为论文展望。

### 成本感知自适应路由

系统新增显式 `--auto` 模式，但不替换原有 ReAct、规划和团队模式。路由器只从
任务文本提取确定性特征，不额外调用模型：任务长度、行动目标数、是否需要检索、
全文、比较、综述、记忆和复杂约束。冷启动时使用可解释的规则；获得离线校准数据
后，对每个模式拟合一个线性效用模型，选择预测效用最高者。

论文中可将单次奖励定义为：

```text
reward = quality - lambda_time * normalized_latency
        - lambda_calls * normalized_llm_calls - lambda_token * normalized_tokens
```

策略文件固定记录特征版本、归一化参数、权重、系数、训练时间和样本摘要。策略缺失、
损坏或特征版本不兼容时，系统自动退回规则路由并显示原因；正式推理默认不使用 UCB
探索，避免真实用户请求影响可复现性。

### 路由实验表

| 对比/消融 | 目的 | 原始数据 | 报告指标 |
|---|---|---|---|
| 固定 ReAct / Plan / Team | 模式基线 | 每题回答与运行指标 JSONL | 质量、耗时、LLM/工具调用、token |
| RuleRouter | 冷启动基线 | 路由决策与理由 JSONL | 同上、类别-模式混淆矩阵 |
| CostAwareRouter | 验证特征化成本效用 | 策略、路由决策与理由 JSONL | 同上 |
| 仅质量奖励 | 去除成本项 | 单独策略与运行 JSONL | 质量/成本权衡 |
| 全局效用 | 去除任务特征 | 单独策略与运行 JSONL | 是否受任务特征增益 |
| 成本权重敏感性 | 改变三项 lambda | 每组独立策略与运行 JSONL | 路由与指标变化 |

任务集在运行前固定为 36 道，按简单、中等、复杂各 12 道划分；校准与留出集严格
隔离。正式实验至少重复两轮。关键词仅可作为任务完成的初筛，最终质量按
`0.40/0.30/0.20/0.10` 的任务完成、事实正确性、引用有效性、输出完整性人工评分
合成，至少 20% 样本由第二位评分者复核。

### 本地模型与离线验证

系统支持 OpenAI 兼容协议,可通过配置切换 DeepSeek、通义千问、Ollama 等模型。
当没有云端 API Key 但本机已安装并启动 Ollama 且存在可用聊天模型时,入口会自动
使用本地模型。离线演示模式 `--demo` 使用假模型剧本,不需要网络和 Key 也能展示
完整 Agent 循环。

## 答辩讲述建议

### 开场 30 秒

我的项目不是简单封装一个大模型聊天接口,而是实现了一个面向科研文献调研的
Agent 框架。它把大模型放到受控工具链中,让模型能够搜索论文、下载和分段阅读、
保存笔记、调用长期记忆,并根据任务复杂度选择 ReAct、规划或多智能体团队模式。

### 演示流程

1. 展示 README 架构图,说明用户可显式进入 ReAct、规划、团队或自动路由模式。
2. 运行离线演示:

   ```powershell
   .venv\Scripts\python main.py --demo
   ```

   说明假模型先要求调用计算器,系统执行工具,再把结果回填给模型。

3. 展示真实检索:

   ```powershell
   .venv\Scripts\python main.py "在 arXiv 上检索 ReAct 论文,给出它的 arXiv 编号"
   ```

   说明回答来自工具结果,不是模型凭空记忆。

4. 展示规划模式:

   ```powershell
   .venv\Scripts\python main.py --plan "调研 ReAct 论文的核心思想并总结"
   ```

   说明复杂任务会先拆步骤,再执行和反思。

5. 展示团队模式:

   ```powershell
   .venv\Scripts\python main.py --team "LLM agent 的记忆机制"
   ```

   说明三个角色通过提示词和工具白名单分工协作。

6. 展示评测:

   ```powershell
   .venv\Scripts\python evals/run_eval.py --mode react --limit 4
   .venv\Scripts\python evals/run_eval.py --mode plan --limit 4
   ```

   说明当前三模式评测框架。

7. 展示自动路由及其解释:

   ```powershell
   .venv\Scripts\python main.py --auto "检索并阅读全文，比较三篇 agent memory 论文，撰写综述和开放问题"
   ```

   说明控制台显示所选模式、理由和预测效用；没有已训练策略时会如实显示回退规则路由。

8. 展示正式实验报告:

   ```powershell
   .venv\Scripts\python evals\run_routing_eval.py --policy data\router\policy.json --quality-only-policy data\router\policy_quality_only.json --global-policy data\router\policy_global.json
   ```

   说明报告中的“未评分”不是失败或零分，而是等待独立人工复核；不能把自动关键词
   命中当成事实正确性。

## 可以强调的亮点

- 从零手写 Agent 框架,能展示模型层、工具层、记忆层、规划层和团队层的内部机制。
- 工具错误回传给模型,让模型有机会修正参数,同时避免程序直接崩溃。
- 文献工具不是只搜索标题,还包含 PDF 下载、坏缓存清理、分段阅读和页内续读。
- 长期记忆使用 JSONL 持久化和手写 BM25,实现了 RAG 的最小闭环。
- 多智能体不是堆多个模型名,而是通过角色提示词和工具白名单限制职责。
- 评测框架支持不同模式的消融对比,可讨论质量、耗时和自动评分局限。
- 支持本地 Ollama,在隐私、成本和离线演示上更适合毕业设计环境。

## 必须讲清楚的边界

- 不要说系统能完全替代研究者;它是科研调研辅助系统。
- 不要说规划模式全面优于 ReAct;现有小样本显示规划模式更慢,优势要在复杂任务上继续验证。
- 不要说评测已经证明准确率 100%;当前任务集规模还小,关键词评分也存在误判。
- 不要说已经完成微调;`finetune/` 目前是 QLoRA 实验脚手架,尚未实际训练。
- 不要说能阅读所有论文全文;扫描版 PDF、图表页和无文字层 PDF 都会限制读取效果。
- 不要说长期记忆是向量语义记忆;当前实现是 BM25 文本检索。
- 不要说多智能体会动态协商;当前是固定流水线,动态调度属于后续扩展方向。

## 论文摘要候选

针对科研文献调研中检索、阅读、记录和总结流程分散且重复劳动较多的问题,本文
设计并实现了一个面向文献调研的自主智能体系统 ScholarAgent。系统基于大语言
模型的工具调用能力,构建了思考、行动、观察交替进行的 ReAct 执行循环,并在此
基础上实现任务规划、反思重试、会话记忆、长期记忆检索和多智能体协作机制。
系统内置 arXiv 检索、OpenAlex 备用检索、论文下载、分段阅读、研究笔记、BM25
长期记忆和计算器等工具,支持云端 OpenAI 兼容模型与本地 Ollama 模型切换。实验
部分构建 JSONL 任务集和自动报告生成流程,用于比较 ReAct、规划和团队模式在任务
完成质量与耗时上的差异。结果表明,该系统能够在受控工具边界内完成基础文献调研
任务,并为复杂科研助手的规划、记忆与协作机制提供了可扩展的工程原型。
