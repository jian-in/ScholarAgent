# 上下文成本控制

Agent 循环每一步都会把完整对话历史重发给模型。一次 `read_paper` 返回约 6000
字符的论文原文,若 8 次读完全文,旧片段会在后续每一步被整段重复计费——这是
长任务 prompt token 的最大浪费。

ScholarAgent 采用**定稿式裁剪**:超过阈值的工具结果在创建时就保头保尾裁剪成
最终形态(默认阈值 4800 字符,保头 3600、保尾 1200;`read_paper` 的续读游标在
结尾,翻页不受影响),并打上标记告知模型原文可重新调用工具获取。此后请求历史
只追加、从不改写,前缀逐字节稳定,DeepSeek 等服务的前缀缓存(命中部分价格更低)
因此全程有效;工具清单跨步固定,运行指标记录缓存命中/未命中 token,工作台显示
命中率。写回会话记忆的也是定稿后的历史,三种执行模式(ReAct/Plan/Team)同时受益。

离线测试(`tests/test_context_compression.py`)校验请求前缀在各步之间保持稳定;
在收紧预算的 6 步读取剧本下,模型收到的总字符量降至不裁剪时的 50% 以下。真实
token 节省幅度取决于任务中长观察的占比。可通过环境变量调整或关闭:

```text
AGENT_CONTEXT_PRUNE_THRESHOLD=4800  # 超过多少字符才裁剪;0=关闭
AGENT_CONTEXT_PRUNE_HEAD=3600       # 保留开头字符数
AGENT_CONTEXT_PRUNE_TAIL=1200       # 保留结尾字符数
```
