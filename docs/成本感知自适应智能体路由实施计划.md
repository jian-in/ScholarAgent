# ScholarAgent 成本感知自适应智能体路由实施计划

## 1. 目标

在保留现有 `react`、`plan`、`team` 三种执行模式的基础上，新增 `auto`
模式。系统先提取任务复杂度特征，再根据历史实验中各模式的任务质量、耗时和
模型调用成本，自动选择综合效用最高的执行模式。

研究问题不是“哪个模式永远最好”，而是：

> 能否根据科研调研任务的特征，在质量与成本之间动态选择更合适的智能体策略？

建议将论文中的方法命名为：

> 面向科研文献调研的成本感知自适应智能体路由方法

## 2. 范围与约束

### 必须完成

- 新增显式 `--auto` 模式；现有默认 ReAct、`--plan`、`--team` 行为保持不变。
- 路由器输出所选模式、预测效用、特征贡献和选择理由，可用于答辩解释。
- 同时提供规则路由基线和成本感知学习路由，便于消融实验。
- 记录质量、总耗时、LLM 调用次数、token 数和工具调用次数。
- 评测数据与日常 `data/` 隔离，训练集与测试集严格分开。
- 没有训练好的策略文件时，自动退化为规则路由，不影响系统使用。

### 本阶段不做

- 不引入 LangChain、向量数据库、深度强化学习或 QLoRA 训练。
- 不重写 Agent、Planner、ResearchTeam 的核心流程。
- 不让真实用户请求在线更新路由策略，以免破坏可复现性。
- 不把 `auto` 设成默认模式，实验充分后再决定。

## 3. 算法设计

### 3.1 路由动作

路由动作集合固定为：

- `react`：单目标、短流程、低成本任务。
- `plan`：存在明确步骤依赖的多步任务。
- `team`：需要多篇检索、全文精读、证据整合和综述写作的复杂任务。

### 3.2 可解释任务特征

第一版使用确定性、可测试的特征提取，不额外调用一次 LLM：

1. 任务文本长度（归一化）。
2. 动作目标数量，如检索、下载、阅读、比较、总结、保存。
3. 是否要求外部文献检索。
4. 是否要求下载或阅读全文。
5. 是否要求比较多篇论文。
6. 是否要求综述、研究脉络或开放问题。
7. 是否要求保存笔记或长期记忆。
8. 是否包含先后依赖、限定年份、数量等复杂约束。
9. 常数偏置项。

特征名称和顺序必须版本化，禁止训练与推理阶段静默不一致。

### 3.3 规则基线

实现 `RuleRouter`，用透明规则完成冷启动。例如：全文阅读、综述和多论文比较
特征同时出现时选择 `team`；多个依赖步骤出现时选择 `plan`；否则选择
`react`。规则和阈值集中定义，不散落在入口代码里。

### 3.4 成本感知学习路由

实现 `CostAwareRouter`。对每个模式分别拟合一个线性奖励模型；可用 LinUCB
的岭回归形式离线校准，避免增加重量级机器学习依赖。允许新增 `numpy`。

单次运行的综合奖励定义为：

```text
reward = quality
         - lambda_time  * normalized_latency
         - lambda_calls * normalized_llm_calls
         - lambda_token * normalized_tokens
```

- `quality` 范围为 `[0, 1]`。
- 成本归一化参数只由校准集计算并写入策略文件。
- 默认权重写入配置，但评测命令必须允许覆盖。
- 训练阶段可使用 UCB 探索项；正式推理默认 `alpha=0`，选择预测效用最大者。
- 策略文件保存特征版本、模式系数、归一化参数、权重、训练时间和样本摘要。

策略文件建议放在 `data/router/policy.json`，示例策略放在
`evals/fixtures/`，真实运行数据不提交仓库。

## 4. 代码结构

### 4.1 新增 `scholaragent/routing.py`

至少包含以下边界：

```python
@dataclass
class RoutingDecision:
    mode: str
    predicted_utility: dict[str, float]
    features: dict[str, float]
    reason: str
    policy_version: str

class TaskFeatureExtractor:
    def extract(self, task: str) -> dict[str, float]: ...

class RuleRouter:
    def route(self, task: str) -> RoutingDecision: ...

class CostAwareRouter:
    def route(self, task: str) -> RoutingDecision: ...

class AdaptiveRunner:
    def run(self, task: str) -> str: ...
```

`AdaptiveRunner` 接收 `{"react": runner, "plan": runner, "team": runner}`，
只负责路由和委派，保持现有 `run(task) -> str` 契约。不得复制三个执行器的逻辑。

### 4.2 新增 `scholaragent/metrics.py`

使用装饰器或轻量包装器统计 LLM 调用数和 token；API 未返回 token 时明确标记为
`None`，不要伪造精确值。工具注册表增加每轮调用计数，但保持现有调用行为不变。

每次运行至少形成：

```python
RunMetrics(
    mode="plan",
    seconds=12.3,
    llm_calls=5,
    prompt_tokens=1200,
    completion_tokens=430,
    tool_calls=3,
)
```

### 4.3 修改入口

- `main.py` 增加 `--auto`，并与 `--plan`、`--team` 做互斥校验。
- 显式模式始终覆盖自动路由。
- 自动路由执行前打印一行简洁解释，例如：
  `路由: team（多论文比较 + 全文精读；预测效用 0.71）`。
- 抽取一个小型 runner 构建函数，避免 `main.py` 与评测入口继续复制组装逻辑；
  只做完成路由所需的最小重构。
- `.env.example` 增加策略路径和成本权重配置。

### 4.4 训练与评测脚本

建议新增：

- `evals/router_tasks.jsonl`：路由专用任务集。
- `evals/calibrate_router.py`：让每道校准题分别运行三种模式并保存完整观测。
- `evals/train_router.py`：读取校准结果，拟合策略并输出 JSON。
- `evals/run_routing_eval.py`：在留出测试集上比较四种策略。

不要让 `train_router.py` 自己调用模型；训练脚本只消费已经保存的实验结果。

## 5. 数据集与实验

### 5.1 任务集

准备至少 36 道科研文献任务，每类 12 道：

- 简单：查标题、作者、编号、年份或单个事实。
- 中等：检索后阅读指定部分、比较两篇论文、保存并召回结论。
- 复杂：多论文精读、方法脉络、证据化综述和开放问题。

任务先固定，再划分校准集和留出测试集；测试题不得参与阈值、归一化参数或模型
系数选择。最终正式结果至少重复两轮，并报告均值和波动。

### 5.2 质量指标

质量分不能只依赖关键词命中。建议组合：

```text
quality = 0.40 * task_completion
        + 0.30 * factual_correctness
        + 0.20 * citation_validity
        + 0.10 * output_completeness
```

- 关键词评分可用于 `task_completion` 的自动初筛。
- 正式论文结果加入人工评分，并保存评分表。
- 至少抽取 20% 样本由第二位评分者复核，报告一致性或分歧率。

### 5.3 对比组

必须报告：

1. 固定 `react`。
2. 固定 `plan`。
3. 固定 `team`。
4. `RuleRouter`。
5. `CostAwareRouter`。

同时做以下消融：

- 去掉成本项，只最大化质量。
- 去掉任务特征，只按全局平均效用选模式。
- 改变 `lambda_time`、`lambda_calls`、`lambda_token`，观察敏感性。

核心结论应回答：自适应路由能否在质量接近最优固定模式的同时，减少耗时和模型
调用成本；不要预设它一定胜出。

## 6. 实施顺序

### 阶段 A：指标与接口

- 为 LLM 和工具调用增加结构化计数。
- 定义 `RoutingDecision`、`RunMetrics` 和策略 JSON 格式。
- 保证现有测试全部通过。

验收：同一任务运行后能读取耗时、LLM 调用次数和工具调用次数；缺失 token 有明确
表示。

### 阶段 B：规则路由与自动执行

- 实现特征提取、`RuleRouter` 和 `AdaptiveRunner`。
- 接入 `main.py --auto`。
- 补齐边界和集成测试。

验收：典型简单、中等、复杂任务分别稳定路由到预期模式；显式模式行为零回归。

### 阶段 C：离线校准与学习策略

- 建立路由任务集和数据划分。
- 跑三种模式，生成不可变的校准 JSONL。
- 实现成本归一化、线性奖励模型训练和策略加载。

验收：固定随机种子时生成相同策略；损坏或版本不兼容的策略文件会安全回退规则
路由并给出提示。

### 阶段 D：正式实验与文档

- 在留出集比较五种策略并生成 Markdown、JSONL 报告。
- 补充 README 架构图、算法公式、命令示例和边界说明。
- 更新毕业论文实验表和答辩演示脚本。

验收：一条命令可复现实验报告；报告包含质量、耗时、调用数、token、路由混淆矩阵
和各任务路由理由。

## 7. 测试要求

- 特征提取：空字符串、中英文、超长输入、否定表达、多个动作词。
- 规则路由：三类典型任务和阈值边界。
- 策略加载：正常、缺失、损坏、特征版本不匹配。
- 成本模型：归一化零方差、缺失 token、效用并列时的确定性选择。
- `AdaptiveRunner`：只执行被选中的 runner，异常不触发其他昂贵模式重跑。
- CLI：`--auto` 与显式模式互斥，原有命令兼容。
- 评测：训练/测试隔离、固定种子、输出字段完整。
- 全量回归：现有 59 项测试必须继续通过。

## 8. 完成定义

只有同时满足以下条件才算完成：

- `--auto` 在真实模型和离线假模型测试中均可用。
- 路由选择可解释、可复现、可安全回退。
- 留出测试集没有参与策略训练或人工调参。
- 五种对比策略与三项消融实验均有原始数据和汇总报告。
- README、论文表述与实际实现一致，不把规则路由包装成学习算法。
- 代码测试全绿，答辩演示可以在独立数据目录一次跑通。
