# 模型分工与超时策略

## 为什么会出现 900 秒提示

工作台的 `[超时]` 来自 `webapp.py` 的后台任务保护阈值，不是 arXiv 的返回内容，也不是死锁。
它是“协作式软超时”：达到阈值后请求任务停止，Agent 会在当前模型调用或工具调用结束、进入下一步边界时收尾。
因此日志中的实际秒数可能略大于 900 秒；如果当时正在等待云端响应或本地模型生成，停止不会强行中断那一次调用。

这个阈值不是系统必须条件，而是防止模型无限调工具、云端费用持续增加或本地任务长期占用资源的保险丝。可在 `.env` 中调整：

```dotenv
SCHOLARAGENT_JOB_SOFT_TIMEOUT_SECONDS=1800
```

用户也可以随时点击“取消任务”。取消同样遵循下一步边界，不强杀线程，避免留下半条工具调用记录。

## 双模型分工

网页工作台默认尝试启用 `split`：

| 阶段 | 模型 | 职责 | 工具边界 |
| --- | --- | --- | --- |
| 外部调研 | 云端模型 | 规划检索、选择工具、读取外部论文资料 | 可使用论文检索、下载、阅读等工具 |
| 内部整理 | 本地 Ollama | 步骤摘要、质量反思、最终综述 | 不接收外部工具清单；写作员只用本地模型 |

Agent 在产生工具证据后才触发本地总结调用；如果没有产生外部证据，不会为了形式上的分工额外调用一次模型。
Plan 的计划/外部调研由云端模型完成，反思、汇总和结构修订由本地模型完成。Team 的检索员、精读员使用云端模型，写作员固定使用本地模型。

每次 `model_step` 事件会记录安全的 `role`、`provider` 和 `model` 字段，网页时间线因此能核验真实分工；密钥不会进入事件或 API 响应。

## 降级与切换

- 云端档案或本地 Ollama 任一端缺失时，工作台会显示“不可用”，默认新任务降级为单模型，并在日志中说明原因。
- 点击“单模型”后，模型下拉框选择的模型负责完整流程；点击“云端检索 · 本地总结”可重新启用分工，前提是两端均已配置。
- 任务提交后会绑定自己的客户端和分工，运行中切换不会改变正在执行的任务。
- 复杂任务建议先使用快速摘要调研，再对少量重点论文做深度精读；不要默认四个方向同时全文阅读。
