# 模型切换与 token 统计

网页工作台（`http://127.0.0.1:8765/`）顶部的模型区域用于查看当前模型、切换模型和
了解一次运行的调用成本。它不是另起一套推理实现，而是复用项目已有的 OpenAI 兼容
模型层。

## 模型来源

- 本地模型来自 Ollama 的 `/api/tags`；工作台会显示模型大小、上下文长度和工具调用能力。
- 只有支持工具调用的聊天模型适合完整的文献调研流程。Embedding、rerank 或不支持
  工具调用的模型不会被当作可用 Agent 模型。
- 云端模型通过 `.env` 中的三个配置项加入选择器：

  ```dotenv
  CLOUD_LLM_BASE_URL=https://api.example.com/v1
  CLOUD_LLM_MODEL=your-model-name
  CLOUD_LLM_API_KEY=your-api-key
  ```

  三项缺一时，工作台只显示本地模型。密钥只在服务端使用，状态接口只返回是否已配置，
  不把密钥发到网页。

## 切换边界

模型切换只改变后续新任务使用的配置。任务开始时会创建并绑定自己的 Agent/LLM 客户端，
因此切换不会中途替换正在执行的任务，也不会让同一个任务前后混用两个模型。
该选择保存在当前服务进程内；重启服务后会按 `.env` 中的 `LLM_*` 配置重新初始化。

## token 统计口径

每次 LLM 调用优先读取 OpenAI 兼容响应中的 `usage.prompt_tokens` 和
`usage.completion_tokens`，运行级指标再将各次调用累加。网页显示：

- 输入 token；
- 输出 token；
- 输入与输出之和；
- LLM 调用次数和工具调用次数。
- 双模型分工开启时，还会按 `research`（调研）和 `summary`（总结）显示各角色的调用与 token，
  便于单独估算云端成本。

如果本地或云端服务没有返回 usage，系统显示“Token 未返回”。这比用字符数、估算比例
或模型上下文长度代替真实 token 更诚实，也避免把估算值误当成账单数据。

## 云端是否会消耗很多

云端费用通常按模型厂商的输入/输出单价计算，基本形式是：

```text
费用 = 输入 token / 1,000,000 × 输入单价
     + 输出 token / 1,000,000 × 输出单价
```

实际单价以所选服务商和模型的当前价格页为准，项目不在代码中硬编码价格。一次简单问答
可能只有一两次模型调用；`Plan`、`Team` 或长论文阅读会因为规划、工具观察、反思和汇总
产生更多调用，输入上下文也会变长，所以成本主要由任务复杂度、调用次数和上下文长度决定。
四路缺口汇总如果没有通过结构检查，还会额外进行一次修订调用；这次调用同样计入网页
显示的 LLM 次数和 token。

本地 Ollama 不产生云端 API token 账单，但会消耗显存、内存、电量和时间。切换到云端前，
先在工作台观察本地运行结果中的 token，再决定是否用云端模型做高质量复核，通常更容易
控制成本。当前工作台的模型切换检查不会自动发起云端推理。
